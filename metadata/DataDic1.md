## 1. Introduction

This document defines every table and column in the ERDP PostgreSQL database `erdp_db`, across the Bronze, Silver, Gold and Audit layers. It serves as the project's Data Dictionary (Sprint 1) and Metadata Repository (Sprint 3).

For each table it records the purpose, the source it is loaded from, the row count from the validated test run, and each column's data type, key role, nullability and business meaning. It lets developers, analysts and reviewers understand the data without reading the SQL or Pentaho code.

The structure was taken from the live database catalogue (`information_schema.columns`), so the types and keys match the implementation exactly. Section 9 gives the query to regenerate the column list after any schema change.

## 2. Data Sources

The platform integrates five source systems of ABC Retail Ltd., each delivered in a different format to cover the five ingestion types required by Sprint 1.

| Source system | File | Format | Records | Pentaho ingestion | Bronze table |
| --- | --- | --- | --- | --- | --- |
| Point of Sale (POS) | pos\_transactions.csv | CSV | 10,000 | CSV file input | stg\_pos\_transactions |
| E-commerce orders | ecommerce\_orders.xlsx | Excel | 5,000 | Microsoft Excel input | stg\_ecommerce\_orders |
| CRM (customers) | customers.json | JSON | 323 | JSON input | stg\_customers |
| Inventory management | inventory.xml | XML | 2,015 | Get data from XML | stg\_inventory |
| Supplier portal | supplier\_orders.sql | SQL | 2,000 | Table input | stg\_supplier\_orders |

The sales and inventory data cover 1–5 December 2010; supplier orders cover January–June 2026. Product codes link sales, inventory and supplier orders, and customer IDs link sales to the CRM.

## 3. Architecture and Naming Conventions

The database follows the Medallion architecture: data moves from raw (Bronze) to cleaned (Silver) to business-ready (Gold), and every pipeline run is logged in Audit.

| Schema | Layer | Purpose | Loaded by |
| --- | --- | --- | --- |
| `bronze` | Raw | Source data landed as-is, plus audit columns | Sprint 1 Pentaho transformations (`t_ingest_*`) |
| `silver` | Cleaned | De-duplicated, standardised and flagged data | `sql/03_silver_cleaning.sql`, run by the master Pentaho job |
| `gold` | Business | Star schema of dimensions and facts for reporting | Sprint 2 Pentaho transformations (`t_gold_*`) |
| `audit` | Logging | ETL run log and rejected rows | Pentaho logging and error handling |

**Naming conventions**

| Pattern | Meaning | Example |
| --- | --- | --- |
| `stg_` | Bronze staging table | stg\_pos\_transactions |
| `dim_` | Gold dimension table | dim\_product |
| `fact_` | Gold fact table | fact\_sales |
| `_id` | Business key, as used in the source system | product\_id |
| `_key` | Surrogate key generated by the warehouse; −1 = Unknown | product\_key |
| `is_` | Boolean flag | is\_return |
| `source_file`, `load_timestamp`, `source_line_id` | Lineage columns that trace a row back to its source | — |

In the column tables below, **PK** = primary key, **FK** = foreign key, and **Nullable = NO** means a value is mandatory. Money values are in GBP.

## 9. Conclusion

The ERDP database holds 21 documented tables: 5 in Bronze, 6 in Silver, 8 in Gold and 2 in Audit (plus Pentaho's own log table). Every Gold row can be traced back to its source file through the lineage columns, and all 21 validation checks passed in the final run.

This dictionary should be updated whenever a table or column changes. The column list can be regenerated from the database with:

```sql
SELECT table_schema, table_name, column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema IN ('bronze', 'silver', 'gold', 'audit')
ORDER BY table_schema, table_name, ordinal_position;
```
